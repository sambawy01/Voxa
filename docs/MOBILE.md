# Mobile builds

Voxa's phone apps are the same Tauri app as the desktop one. The Android and iOS projects
are generated by Tauri, not committed. CI builds them unsigned on every change
(`.github/workflows/app.yml`: the `android` job; iOS follows in roadmap M10c). Signing and store listings need
the owner's accounts; see "Blocked on owner" in [APP_ROADMAP.md](APP_ROADMAP.md).

## Android

Needs the Android SDK and NDK (`ANDROID_HOME`, `NDK_HOME`), Java 17 and
`rustup target add aarch64-linux-android`. From `app/`:

```sh
npm ci
npx tauri android init --ci
python3 -I tools/android_setup.py src-tauri/gen/android   # microphone permission
CARGO_TARGET_DIR=$PWD/src-tauri/target npx tauri android build --apk --target aarch64
```

**Set `CARGO_TARGET_DIR` as shown.** sherpa-onnx's build script copies its Android
libraries (`libsherpa-onnx-c-api.so`, `libonnxruntime.so`) into
`gen/android/app/src/main/jniLibs` only when Cargo's target folder is next to
`tauri.conf.json`. The workspace's own folder, `app/target`, is not next to it, so the
script quietly skips the copy. The APK then builds but fails to load at start. CI checks
the APK for these libraries and for the `RECORD_AUDIO` and `INTERNET` permissions.

The APK is unsigned (`app-universal-release-unsigned.apk`). To install it on a test phone,
sign it with a debug key, or build with `--debug` for a debug-signed APK.

## Phone differences

- **Device ID for licences.** Phones give apps no machine ID, so Voxa keeps a random ID in
  its data folder. Reinstalling the app makes a new ID, which counts as a new device until
  the old one is deactivated, or until all devices are released with "Lost or broken a
  device?".
- **No voice pack import.** Phones can't pick a folder, so "Import voice pack" is hidden
  and voices come from the catalogue.
- **Layout.** `tests/layout.test.mjs` checks the UI at 360 and 390 px.
